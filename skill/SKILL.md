# Legnext: Midjourney через REST в Hermes

Плагин `~/.hermes/plugins/legnext/` даёт 4 инструмента: `mj_imagine`,
`mj_job`, `mj_action`, `mj_balance`. Ключ `LEGNEXT_API_KEY` в `~/.hermes/.env`.

## When to Use

- генерация картинок через Midjourney из Hermes;
- доработка плагина (новые эндпоинты: blend, describe, inpaint, video);
- перенос обёртки на другой MCP-клиент;
- отладка «инструмент не виден» или ошибок Legnext.

## Midjourney не имеет официального API

Любой «Midjourney API» это посредник, автоматизирующий Discord-бота.
Legnext держит ферму аккаунтов (поэтому «no Midjourney account required»),
ToS-риск переложен на них, но бан их аккаунтов роняет твою интеграцию.
Альтернативы: PiAPI, useapi.net, ImaginePro, GoAPI.

## MCP у Legnext НЕ генерирует

`https://docs.legnext.ai/mcp` это docs-поиск по документации, без ключа.
Генерацию он не умеет. Подцепить MCP вместо плагина нельзя. MCP полезен
только как источник правды по полям, чтобы не выдумывать схему.

## Асинхронность не ложится на image_gen

Слот `image_gen` в Hermes ждёт синхронный ответ (запрос → картинка).
Legnext это submit → job_id → polling → delivery URL → скачать.
Поэтому отдельный плагин, а не провайдер image_gen и не cliproxy
(cliproxy говорит на chat/completions, про Legnext не знает).

## Контракт API (проверено курлом, лендинг врёт)

Base: `https://api.legnext.ai/api`. Заголовок `x-api-key` на submit и account.

**Лендинг legnext.ai показывает поля `model`/`mode`/`aspectRatio` у
`/v1/diffusion` — их НЕТ.** API-reference: только `text` и `callback`.
Все параметры Midjourney идут флагами ВНУТРИ строки `text`:
`--v 8.2`, `--ar 16:9`, `--niji 6`, `--hd`, `--sref`, `--cref`, `--no`.
Доверяй `docs.legnext.ai/api-reference`, не лендингу.

| Endpoint | Тело |
|---|---|
| `POST /v1/diffusion` | `{text, callback?}` |
| `POST /v1/upscale` | `{jobId, imageNo, type, callback?}` |
| `POST /v1/variation` | `{jobId, imageNo, type, callback?, remixPrompt?}` |
| `POST /v1/reroll` | `{jobId, callback?}` |
| `GET /v1/job/{job_id}` | **без ключа** |
| `GET /account/balance` | **без `/v1`** в пути |

`GET /account/balance` — единственный путь без `/v1`. Легко ошибиться.

## imageNo индексируется С НУЛЯ, и есть required `type`

`imageNo` это **0-3** для обычной сетки (0-23 для `--draft` v8.1/v8.2).
Валидация вида `number < 1` отрезает первую картинку сетки.
Сверяйся с `available_actions` родительской задачи: оно отдаёт
`{"reroll": true, "upscale": [0,1,2,3], "variation": [0,1,2,3]}`.

У upscale и variation есть **required поле `type`** (enum integer):

- upscale: `0` = subtle, `1` = creative. 2 (v5 2x) и 3 (v5 4x) deprecated.
- variation: `0` = subtle, `1` = strong.

У reroll полей кроме `jobId` НЕТ.

Если проверять follow-up на нулевом балансе, 402 приходит ДО валидации
тела — отсутствие required-поля так не вскрывается. Форма тела
считается проверенной только после живого 200 на положительном балансе.

## remixPrompt заменяет промпт целиком

Variation с `remixPrompt` теряет флаги родителя: задача с `--ar 16:9`
отдала variation 1024×1024. Если нужна та же геометрия, дублируй `--ar`
внутри самого remix-промпта.

## Биллинг считает в двух единицах

При списании берётся блок 1000 кредитов, остаток возвращается в `points`:
$10 → 4 задачи (400 кредитов) → `credits: 9000, points: 600, balance_usd: 9.6`.
**`available_credits` не показывает реальный остаток.** Для «хватит ли»
смотри `balance_usd` либо сумму credits + points.

## Неподтверждённое происхождение CDN-хоста

В живых ответах API файлы приходили с `images.sexapi.ai`. Этот хост
возвращал 200 и `image/png` через Cloudflare; Legnext в документации
называет ссылки временными CDN URL, но не упоминает конкретный домен.
Принадлежность `sexapi.ai` Legnext или связь с NSFW-сервисом НЕ
подтверждены. Не утверждать такую связь по одному названию домена.
Страница [Output Storage](https://docs.legnext.ai/getting-started/output-storage) на момент проверки говорит 7 дней, а [task-lifecycle.md в vendor skill](https://github.com/legnext-ai/skills/blob/main/legnext/references/task-lifecycle.md) пишет «no more than 30 days»; источники противоречат друг другу. Не обещай клиенту точный TTL, скачивай результат сразу. Окно поиска задачи и follow-up составляет 3 суток, это отдельный срок. Для корпоративного контура уточнять у
Legnext принадлежность хоста и возможность другого delivery-домена.

## Vendor skill и первичная спецификация

Официальный [Legnext skill](https://github.com/legnext-ai/skills/tree/main/legnext) содержит методику интеграции, а не исполняемый инструмент. До доработки плагина сверяй его `SKILL.md` и ссылки в `references/`, затем точные поля тела в [OpenAPI](https://docs.legnext.ai/openapi.yaml). Skill не заменяет проверку эндпоинта: например, у upscale/variation обязательно поле `type`, которого в vendor skill нет.

- Без `--v` Legnext использует v7, не последнюю версию сайта. Плагин добавляет `--v 8.2` по умолчанию, только когда в промпте нет `--v`/`--niji` и не передан `version`; это дефолт текущей интеграции, не механизм автообновления на будущую версию.
- Комбинации версии и флагов сверяй с [машинной схемой](https://docs.legnext.ai/schemas/mj-image-params.v1.json); параметры образца на маркетинговой странице не контракт.
- Для качества промпта смотри [basics](https://docs.legnext.ai/getting-started/prompting-basics) и [advanced](https://docs.legnext.ai/getting-started/prompting-advanced); текст сцены, объекта и света важнее набора общих эпитетов. Флаги ставь в конце `text`.
- Кредиты: submit замораживает `meta.usage.frozen`, при успехе стоимость переходит в `meta.usage.consume`, при провале резерв освобождается. `--hd` на v8.1/8.2 ориентировочно ×1.5, `--turbo` ×2; фактическую стоимость читай из usage и актуального тарифа.
- `available_actions` у родительской задачи только подсказка: провайдер может вернуть 400 даже для перечисленного действия. Не повторяй его бесконечно.

## `--style raw` ломает v8.2

С `--v 8.2` флаг `--style raw` даёт `failed: invalid prompt parameter` (кредиты не списываются). Не добавляй его; фотореализм задавай словами сцены и света.

## Серия коммерческих изображений под существующий сайт

1. До платной генерации изучи живую страницу и изображения товаров, затем проверь, где именно используется будущая картинка: пропорции, `background-size`/кроп, фон карточки, минимальный размер миниатюры. Сними палитру и характер света/фотографий с сайта. Не принимай «премиум» за универсальный стиль: для этого пользователя результат должен выглядеть вкусно и продавать именно в контексте его сайта.
2. Для первого раздела сделай несколько **различимых направлений** (например, светлая предметная съёмка, более декоративная ботаника, тёмный editorial), а не сразу всю серию. Различай фотографию и иллюстрацию в подписи по фактическому результату, не только по промпту. Указывай стоимость платных проб.
3. Скачай результаты локально и собери подписанный контактный лист. Проверь каждый кандидат в реальном соотношении сторон и в минимальном размере использования: крупный красивый кадр может превратиться в неразборчивое пятно в чипе. Оцени силуэт, контраст, запас под кроп, цвет упаковки, наличие рук/людей, текста и генеративных дефектов. По возможности покажи вариант прямо в макете карточки рядом с существующими товарами.
4. Покажи лист и короткую рекомендацию, дождись выбора художественного направления до платного тиражирования разделов. После выбора используй подходящий референс (`--sref`, если применим) и единые композиционные ограничения, но проверяй каждую итоговую картинку: референс не гарантирует консистентность и читаемость.

## Webhook или polling

Локальный Hermes работает через polling с ограниченным ожиданием. Для серверной интеграции webhook может уменьшить задержку, но доставка может повторяться или пропадать: быстро отвечай 2xx, дедуплицируй по `job_id`, сверяй каноническое состояние через GET job и держи polling как восстановление. Публичного signing secret у callback сейчас нет: делай трудноугадываемый путь, проверяй метод/тип/форму тела и не доверяй одному callback.

## Ошибки и повторные запросы

Классифицируй по HTTP-коду и категории ошибки, не по точной строке провайдера. 400 = исправить поля/флаги или контент; 401 = проверить ключ; 402 = пополнить баланс; 403 = ограничение аккаунта/контента; 404 GET job = неверный или просроченный идентификатор; 429 = подождать доступной ёмкости и применять backoff; временные 5xx/сеть = ограниченные повторы; устойчивые 5xx = остановиться и обратиться в поддержку. `raw_message` может содержать служебные детали, не показывай клиенту без фильтрации. При `failed` повторяй submit только если причина действительно временная. Если ответ submit потерян после отправки, результат неоднозначен: сервер мог создать оплачиваемую задачу. У API нет idempotency key, не обещай exactly-once.

## Жизненный цикл

Терминальные состояния только `completed` и `failed`. Ждать через
`pending`, `staged`, `processing`, `retry`. Статус `retry` значит Legnext
сам перезапускает задачу — вторую НЕ создавать.

- `output` равен null пока статус не `completed`.
- Клиентский таймаут не отменяет серверную задачу: вернуть `job_id`
  и дожидаться позже через `mj_job`, не делать повторный submit.
- **Дедупликации по промпту нет: каждый повторный POST = новая платная
  задача.** Ретраи submit только когда `job_id` ещё не получен.
- `job_id` это capability-токен: даёт доступ к результату без ключа.
  Держать вне публичных логов и URL.
- Окно поиска задачи 3 суток, потом `GET /v1/job` отдаёт 404.
- URL результата временный; официальные источники расходятся по сроку (7 или не более 30 дней). Скачивать локально сразу после `completed`.

## Расценки

$1 = 1000 кредитов. Fast generation 80 (= $0.08 за сетку из 4 картинок),
turbo 160, variation 120, standard upscale 120, creative upscale 160,
describe/shorten 20, видео 480p 480, 720p 1536.

BYOK: $20/мес из кредитов, fast-image задачи идут на свою подписку MJ
бесплатно. Окупается примерно от 250 генераций в месяц.

НЕ считать «хватит ли денег» вычитанием хардкод-цен в коде —
документация Legnext это прямо запрещает, цена зависит от параметров.
Звать `mj_balance` (бесплатно) до дорогой задачи и после 402.

## Пилтфалы Hermes-плагина

- **`kind: tool` не существует.** Валидные значения в
  `hermes_cli/plugins_manifest.py::_VALID_PLUGIN_KINDS`:
  `standalone, backend, exclusive, platform, model-provider`.
  Для tool-плагина это `standalone` (он же дефолт). Невалидный kind не
  роняет загрузку — только warning, инструменты всё равно регистрируются,
  поэтому ошибку легко не заметить.
- **Плагины opt-in.** После создания файлов нужен
  `hermes plugins enable <name>`, иначе инструментов не будет.
  Проверка статуса: `hermes plugins list --plain --no-bundled`.
- **Ключ только через `agent.secret_scope.get_secret`**, не `os.environ`:
  один процесс обслуживает несколько профилей, env утечёт чужой секрет.
  Импорт ленивый, внутри функции, с fallback на env если Hermes не в path.
- **Пути через `hermes_constants.get_hermes_home()`**, никогда не `~/.hermes`.
- Handler: `def h(args: dict, **kwargs) -> str`, ВСЕГДА json.dumps,
  никогда не поднимает исключение наружу.

## Проверка после правок

```bash
cd ~/.hermes/hermes-agent && venv/bin/python -c "
import model_tools
from tools.registry import registry
print(sorted(registry.get_tool_names_for_toolset('legnext')))
print('available:', registry.is_toolset_available('legnext'))
"
```

У `ToolRegistry` НЕТ метода `list_tools()`. Правильные:
`get_all_tool_names()`, `get_tool_names_for_toolset(ts)`,
`get_toolset_for_tool(name)`, `is_toolset_available(ts)`.

Живой вызов через реальный dispatch:

```bash
venv/bin/python -c "
import model_tools
print(model_tools.handle_function_call('mj_balance', {}))
"
```

**Второй аргумент `handle_function_call` это dict, НЕ JSON-строка.**
Если передать строку, все args молча станут пустыми и любой вызов
вернёт ошибку валидации первого поля — выглядит как баг плагина,
хотя баг в тесте.

Бесплатные проверки логики (кредиты не тратят): невалидный `job_id`,
`mj_action` без `image_no`, `image_no` вне 0-23, `mode` не 0/1,
`remix_prompt` на upscale, пустой `prompt`, `aspect_ratio: "wide"`,
`mj_job` с несуществующим UUID (даёт живой 404).

Платные ветви проверяй по одной задаче на сценарий. upscale и reroll
от одного родителя можно гонять параллельно, лимит стандартного
аккаунта 6 одновременных задач.

Не проверено и искусственно не вызывается: статусы `staged` и `retry`
(нужна занятая очередь или сбой провайдера), таймаут с resume.
