# Legnext/Midjourney в Hermes: эксплуатация и перенос

Плагин `legnext` добавляет в Hermes четыре инструмента для работы с неофициальным Midjourney API через Legnext. Генерация и действия с изображениями платные; проверка баланса и чтение задачи не создают новую платную задачу. Midjourney напрямую этот API не предоставляет: доступность сервиса и правила использования зависят от посредника Legnext.

## Что именно установлено

- **Hermes-плагин**: каталог `legnext` с `plugin.yaml`, `__init__.py`, `schemas.py`, `tools.py`, `client.py`. Он регистрирует инструменты `mj_imagine`, `mj_job`, `mj_action`, `mj_balance` в toolset `legnext`, вызывает Legnext REST API и сохраняет завершенные изображения локально. Это не замена встроенному `image_gen`.
- **Vendor skill**: [legnext-ai/skills](https://github.com/legnext-ai/skills/tree/main/legnext) описывает методику интеграции Legnext для разработчика. Сам по себе skill не устанавливает эти четыре инструмента и не генерирует изображения. Его параметры и условия сверяйте с актуальной [документацией Legnext](https://docs.legnext.ai/).
- **Legnext docs MCP**: [документационный MCP](https://docs.legnext.ai/mcp) предназначен для поиска по документации, а не для отправки платных задач. Подключение MCP не заменяет плагин.

Плагин работает асинхронно: отправка задачи дает `job_id`; затем задача опрашивается до `completed` или `failed`. Результат содержит локальные файлы и временные URL. Не путайте `job_id` с номером картинки.

## Подготовка и установка (администратор)

Нужны работающий Hermes Agent с настроенной моделью, доступ к `https://api.legnext.ai/`, учетная запись Legnext с действующим API-ключом и средства на платные операции. Ключ создается в [кабинете Legnext](https://legnext.ai/dashboard). Плагин использует Python-пакет `httpx` из окружения Hermes; при ошибке импорта проверьте зависимости установки Hermes. Инструкции по базовой установке Hermes: [официальный quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart).

На этой машине плагин уже находится в `~/.hermes/plugins/legnext/` и включен. Для другого Hermes самый простой перенос без репозитория: перенесите целиком каталог `legnext` с исходной машины в `$HERMES_HOME/plugins/legnext/` целевой машины (при обычной установке `$HERMES_HOME` соответствует `~/.hermes`). Скопируйте исходники и manifest, не переносите `.env`, личные изображения или токены. Если каталог уже есть, сначала сравните содержимое и сохраните резервную копию; не накладывайте копию поверх рабочей версии вслепую. После копирования на целевой машине выполните:

```bash
hermes plugins enable legnext
hermes plugins validate "$HOME/.hermes/plugins/legnext"
hermes plugins doctor legnext
hermes plugins list --plain --no-bundled
```

При нестандартном профиле/`HERMES_HOME` замените путь в `validate` на фактический путь к скопированному каталогу. `enable` включает плагин; `validate` проверяет manifest, объявленные инструменты, импорт и безопасность; `doctor` загружает его по реальным контрактам Hermes и проверяет регистрацию. В `list` строка `legnext` должна иметь статус `enabled`. Откройте новую сессию Hermes после включения; ранее начатая сессия может не получить новый набор инструментов.

**Секрет настраивается отдельно в активном профиле каждой установки.** Узнайте расположение файла секретов командой `hermes config env-path`, откройте указанный `.env` локальным редактором и добавьте строку `LEGNEXT_API_KEY=<ваш_ключ>` (плейсхолдер заменить только внутри файла). Не вводите значение в чате, историю терминала, `config.yaml`, документацию, Git или скриншоты. Ограничьте чтение `.env` владельцем файла. При использовании именованных профилей выполняйте административные команды именно в нужном профиле и убедитесь, что редактируете его `.env`, а не файл другого профиля. `hermes plugins validate` и `doctor` не заменяют проверку действительности ключа; после настройки попросите Hermes вызвать бесплатный `mj_balance`, не отправляя платную задачу. При 401 проверьте ключ в кабинете Legnext и активный профиль.

Настройки из `plugin.yaml`: `output_dir` (по умолчанию `<HERMES_HOME>/legnext-output`), `poll_interval` (5 секунд), `default_timeout` (600 секунд), `default_version` (`8.2`). Изменяйте параметры через `hermes config set`, а не вручную в `config.yaml`, например:

```bash
hermes config set plugins.entries.legnext.settings.output_dir "$HOME/Pictures/legnext"
hermes config set plugins.entries.legnext.settings.default_version 8.2
```

Убедитесь, что у Hermes есть право записи в выбранный каталог. Значение `default_version` в текущем `plugin.yaml` равно `8.2`; строка в старом `README.md` про пустой default устарела. Приоритет у версии в тексте запроса (`--v 7`, `--v 8.2`, `--niji 6`), затем у параметра инструмента `version`, затем у `default_version`. Если задать пустое значение по умолчанию и не указать версию ни в запросе, ни в инструменте, версия останется на усмотрение Legnext (по описанию manifest, API использует v7).

### Распространение через Git (только после публикации)

Если вы **сами опубликовали и проверили** отдельный репозиторий с этим плагином, на других машинах можно использовать `hermes plugins install <реальный-Git-URL> --no-enable`, затем `hermes plugins enable legnext` и проверки выше. `<реальный-Git-URL>` здесь плейсхолдер, готовой публичной ссылки на этот плагин нет. Не выдавайте репозиторий vendor skill `legnext-ai/skills` за репозиторий плагина. До публикации используйте перенос каталога. Перед публикацией проверьте, что в Git нет ключей, `.env`, приватных `job_id` и результатов клиентов. `--no-enable` дает возможность сначала проверить установленный код и только затем включить его.

## Работа (конечный пользователь)

В обычном чате Hermes попросите агента использовать инструменты `mj_*`, если он выбирает другой генератор. Не вставляйте API-ключ в запрос. Каждая новая генерация, variation, upscale и reroll может списать деньги. Сначала попросите проверить баланс, затем подтвердите нужный платный вызов.

Примеры запросов:

> Проверь баланс Legnext инструментом `mj_balance`. Никаких платных задач пока не создавай.

> Создай через `mj_imagine` сетку: «вечерний вокзал под дождем, акварель, мягкий свет --ar 16:9 --v 8.2». Проверь баланс перед отправкой; дождись завершения и сообщи локальные пути PNG.

> Отправь только одну генерацию через `mj_imagine` с `wait=false`: «сосновый лес в тумане --ar 3:2». Верни приватный `job_id`, не отправляй задачу повторно.

> Возобнови задачу `job_id=<UUID_ИЗ_ОТВЕТА>` через `mj_job` с `wait=true`, `download=true`; когда закончится, покажи локальные пути файлов. Не отправляй новый `mj_imagine`.

> Для родительской задачи `job_id=<UUID_РОДИТЕЛЯ>` проверь `available_actions`. Сделай `mj_action` с `action=variation`, `image_no=0`, `mode=1`, `remix_prompt="сосновый лес на рассвете --ar 16:9"`. Перед платным действием проверь баланс.

`job_id` здесь намеренно только плейсхолдер. Реальный ID не публикуйте: чтение задачи по нему не требует API-ключа, он дает доступ к результату. В обычной сетке первое изображение имеет `image_no=0`, четвертое `image_no=3`, а не 1 и 4. Для `--draft` допустимый диапазон может быть 0-23; сверяйтесь с `available_actions` родительской задачи. Даже объявленное доступным действие иногда отклоняется провайдером.

| Инструмент | Для чего | Точные поля из схемы |
| --- | --- | --- |
| `mj_balance` | Бесплатно читает баланс | Аргументов нет. Возвращает `balance_usd`, `available_credits`, `available_points` и служебные поля аккаунта. |
| `mj_imagine` | Создает одну платную генерацию | `prompt` (обязательная непустая строка, итоговый текст 1-8192 символов), `aspect_ratio` (необязательно, формат `16:9`), `version` (необязательно, например `8.2` или `niji 6`), `wait` (по умолчанию `true`), `timeout` (положительное целое число секунд для ожидания). `aspect_ratio` дописывает `--ar`, только если его нет в `prompt`; версия аналогично добавляется при отсутствии `--v`/`--niji`. |
| `mj_job` | Смотрит статус существующей задачи и при необходимости докачивает результат | `job_id` (обязательный UUID), `wait` (по умолчанию `false`), `timeout` (для ожидания), `download` (по умолчанию `true`). При завершении с `download=true` сохраняет локальные файлы. |
| `mj_action` | Создает платный `upscale`, `variation` или `reroll` | `action` и родительский `job_id` обязательны; `image_no` обязателен для upscale/variation, для reroll не нужен; `mode` 0 или 1, по умолчанию 0; `remix_prompt` только для variation; `wait` (по умолчанию `true`), `timeout` (при ожидании). |

Для `mj_action`: `mode=0` означает `subtle` и для upscale, и для variation; `mode=1` означает `creative` для upscale и `strong` для variation. Флаги Midjourney (`--ar`, `--v`, `--niji`, `--hd`, `--sref`, `--no` и т. п.) пишутся **в тексте prompt**, а не как произвольные JSON-поля API. Плагин самостоятельно дописывает только `--ar` из `aspect_ratio` и версию из `version`/настройки. `remix_prompt` заменяет исходный текст промпта: если нужно сохранить широкое соотношение сторон, повторите `--ar 16:9` вручную внутри `remix_prompt`. Без него variation может стать квадратной.

При `wait=false` отправка возвращает `job_id` и текущий статус, **не готовое изображение**. Позже вызовите `mj_job` с тем же `job_id`, `wait=true`, `download=true`; если ожидание прервалось по `timeout`, серверная задача не отменяется. Не создавайте новый платный POST только из-за таймаута или неопределенного ответа сети: сервис мог принять первый запрос, а повторный может списать деньги снова. Возможные промежуточные статусы: `pending`, `staged`, `processing`, `retry` (в последнем случае Legnext повторяет задачу сам). Конечные: `completed`, `failed`.

Завершенные изображения плагин скачивает в `output_dir` и возвращает `files` (пути), `image_urls`, `job_id`, `status`, `available_actions` и, если доступны, сведения о расходе. В проверенных генерациях были PNG: обычная сетка из четырех PNG, upscale один PNG. Формат/число файлов зависят от операции и ответа сервиса; проверяйте фактические `files` и расширения. По [документации о хранении результатов](https://docs.legnext.ai/getting-started/output-storage) CDN-ссылки временные: там указан срок 7 дней, тогда как vendor skill пишет «не более 30 дней». Источники расходятся, поэтому точный срок не гарантирован — скачивайте и сохраняйте результат сразу. Не полагайтесь на URL вместо своей копии. **Поиск задачи и действия над исходной задачей доступны в течение трех суток с ее создания**; сохранение PNG это окно не продлевает.

## Деньги и диагностика

Ориентир по схеме и наблюдавшимся заданиям: $1 соответствует 1000 кредитам; fast-генерация около 80 кредитов (около $0.08 за сетку), variation около 120, стандартный upscale около 120, creative upscale около 160, Turbo-генерация около 160. Это не тарифная гарантия: цена зависит от модели и параметров, проверяйте текущие условия Legnext и `mj_balance` перед отправкой. Смотрите прежде всего `balance_usd`: `available_credits` в одиночку не учитывает остаток `available_points`. После HTTP 402 снова проверьте баланс, пополните счет и только затем осознанно создавайте новую задачу.

| Симптом | Действие |
| --- | --- |
| Инструменты не находятся | Администратор проверяет `hermes plugins list --plain --no-bundled`, `hermes plugins doctor legnext`, активный профиль и запуск новой сессии. |
| `LEGNEXT_API_KEY отсутствует`, HTTP 401 | Проверьте файл из `hermes config env-path`, правильный профиль, срок действия ключа. Не отправляйте ключ в чат или логи. |
| HTTP 400 | Проверьте строку запроса, флаги, `image_no`, разрешенные `available_actions`; возможна модерация. Не повторяйте запрос без исправлений. |
| HTTP 402 | Недостаточно средств: проверьте `mj_balance`; повторный POST только после пополнения и решения пользователя. |
| HTTP 403 | Проверьте ограничения аккаунта, модерацию и лимит ошибок в кабинете Legnext. |
| HTTP 404 | Проверьте UUID и трехдневное окно задачи. Если окно прошло, локальная копия сохраняется, но follow-up недоступен. |
| HTTP 429 | Слишком много одновременных задач. Дождитесь свободного слота, не дублируйте уже созданные задачи. |
| `timed_out=true` или прерван опрос | Продолжите по известному `job_id` через `mj_job`; это не отмена и не основание для повторного submit. |
| `completed`, но `files` пусты или ошибка скачивания | Проверьте `output_dir`, права записи, сеть и временный URL; вызовите `mj_job` с `download=true`, пока ссылка доступна. |

Границы испытаний этой версии: на живом сервисе проверены обычная генерация, subtle upscale, reroll, strong variation с remix; **не проверены** статусы `staged` и `retry` под реальной нагрузкой, клиентский таймаут с последующим resume и все комбинации `--draft`/`image_no=0-23`. Эти ветви предусмотрены кодом, но не следует выдавать их за подтвержденные живым испытанием. Механизм восстановления неизвестного `job_id` после неопределенного POST-ответа не реализован; без ID не повторяйте платную отправку автоматически, сначала выясните состояние в кабинете Legnext/поддержке.

Для параметров именно этого установленного плагина первичны локальные `schemas.py`, `tools.py`, `client.py`, `plugin.yaml`.
