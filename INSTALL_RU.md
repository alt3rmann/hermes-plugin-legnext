# Установка Legnext/Midjourney на другой Hermes

Инструкция для машины, где Hermes **уже установлен и работает**. Переносятся две независимые вещи плюс секрет:

| Что | Зачем | Обязательно |
|---|---|---|
| Плагин `legnext` | даёт 4 инструмента `mj_*` | да |
| Ключ `LEGNEXT_API_KEY` | без него работает только чтение задач | да |
| Скилл `legnext-midjourney-api` | знания для доработки и отладки | нет |

Скилл не нужен для генерации картинок. Он нужен тому, кто будет править плагин или разбирать ошибки.

## 1. Плагин

```bash
hermes plugins install alt3rmann/hermes-plugin-legnext --no-enable
hermes plugins enable legnext
```

`--no-enable` позволяет сначала посмотреть установленный код, затем включить. Проверка:

```bash
hermes plugins list --plain --no-bundled   # ожидается: enabled  git  0.1.0  legnext
hermes plugins doctor legnext              # загрузка по реальным контрактам
```

Воспроизводимая установка с закреплением ревизии: `hermes plugins install alt3rmann/hermes-plugin-legnext --ref <40-символьный-SHA>`.

**Не запускайте `plugins install` там, где Hermes ещё не развёрнут.** При пустом `HERMES_HOME` команда сначала готовит изолированный runtime и тянет зависимости самого Hermes (numpy, pillow, ctranslate2 и прочее) — это десятки минут и выглядит как зависание. Проверено: на пустом каталоге процесс не завершился за 8 минут.

### Если каталог скопирован вручную

Копирование каталога в `$HERMES_HOME/plugins/legnext/` работает, но такая установка не отслеживается и не обновляется. Если у каталога есть git-remote, превратите её в отслеживаемую:

```bash
hermes plugins adopt legnext
```

Вывод подтвердит источник и ревизию. После этого работают `hermes plugins check-updates` и `hermes plugins update legnext`.

При копировании не переносите `.env`, каталог с готовыми картинками и `__pycache__`.

## 2. Ключ

Ключ настраивается на каждой установке отдельно, он не переносится вместе с кодом.

```bash
hermes config env-path    # покажет путь к файлу секретов активного профиля
```

Откройте указанный файл **локальным редактором** и добавьте строку:

```
LEGNEXT_API_KEY=<ключ из кабинета Legnext>
```

Ключ берётся в [кабинете Legnext](https://legnext.ai/dashboard). Не вводите его значение в чат агента, в историю терминала, в `config.yaml`, в документацию и в git. Права на файл секретов — только владельцу (`chmod 600`).

Проверка — бесплатным инструментом, без платной задачи. В новой сессии Hermes:

> Проверь баланс Legnext инструментом `mj_balance`. Платных задач не создавай.

При ошибке 401 проверьте ключ в кабинете и что вы редактировали файл нужного профиля.

## 3. Скилл (необязательно)

```bash
hermes skills install https://raw.githubusercontent.com/alt3rmann/hermes-plugin-legnext/main/skill/SKILL.md --yes
```

Два предостережения, оба проверены на практике:

**Установка идёт под именем из frontmatter**, то есть `legnext-midjourney-api`, независимо от `--name`. Если на машине уже есть скилл с таким именем, он будет перезаписан. Сохраните копию, если правили его под себя.

**`raw.githubusercontent.com` кеширует ветку `main` на несколько минут.** Сразу после выхода новой версии команда может поставить предыдущую. Когда нужна точная версия, ставьте по SHA коммита вместо `main`:

```bash
hermes skills install https://raw.githubusercontent.com/alt3rmann/hermes-plugin-legnext/<SHA>/skill/SKILL.md --yes
```

Перед установкой скилл можно прочитать не устанавливая: `hermes skills inspect <URL>`.

Установку скиллов проверяет сканер безопасности, и он блокирует high-risk находки даже с `--force`. Срабатывает он и на безобидный текст: упоминание пути к файлу секретов и слова `os.environ` в советах по безопасности дали два high-risk срабатывания, хотя никакого кода в скилле нет. Если ставите свою правленую версию и получили отказ — дело может быть в формулировке, а не в реальной угрозе; посмотрите, на какие правила он сослался.

## 4. Проверка целиком

После установки **откройте новую сессию Hermes**: набор инструментов формируется при старте сессии, уже запущенная их не увидит.

```bash
hermes plugins list --plain --no-bundled   # legnext → enabled
hermes plugins doctor legnext              # 4 инструмента зарегистрированы
hermes config env-path                     # файл существует, ключ внутри
```

В чате, по возрастанию стоимости:

> Проверь баланс Legnext через `mj_balance`.

Затем одна платная генерация (порядка $0.08 за сетку из 4 картинок):

> Создай через `mj_imagine`: «вечерний вокзал под дождём, акварель, мягкий свет --ar 16:9». Дождись готовности и покажи локальные пути PNG.

Файлы попадут в `output_dir` — по умолчанию `<HERMES_HOME>/legnext-output`.

## Настройки

Меняются командой `hermes config set`, не правкой `config.yaml` вручную:

```bash
hermes config set plugins.entries.legnext.settings.output_dir "$HOME/Pictures/legnext"
hermes config set plugins.entries.legnext.settings.default_version 8.2
```

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `output_dir` | `<HERMES_HOME>/legnext-output` | куда скачиваются PNG |
| `poll_interval` | 5 | секунд между опросами задачи |
| `default_timeout` | 600 | предел ожидания одной задачи |
| `default_version` | `8.2` | версия Midjourney, если не указана в запросе |

Про `default_version`: **если оставить его пустым, Legnext использует v7**, а не новейшую версию. Приоритет такой: флаг `--v`/`--niji` в тексте запроса → параметр `version` у инструмента → эта настройка.

## Что проверено, а что нет

Проверено живьём на исходной машине: публикация репозитория, клон с GitHub, `plugins adopt` с переводом в git-установку, `plugins validate` (13 проверок), `plugins doctor`, установка скилла по URL с SHA (verdict SAFE), подстановка `--v 8.2` по умолчанию без обращения к платному API.

**Не проверено end-to-end:** сама команда `plugins install` с GitHub на чистой машине. Проверено только, что репозиторий клонируется, а код после установки корректно принимается Hermes через `adopt` и `doctor`. На целевой машине первую установку стоит выполнить с `--no-enable` и посмотреть результат до включения.
